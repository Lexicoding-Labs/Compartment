# Compartment implementation plan

Deliver the attended integration-change audit first, followed by reliability, portability and evaluation gates. Seed Planning & Coordination, Research & Intelligence, Execution & Integrations, Quality & Assurance and Reliability & Operations. Each department has exactly one Director, one Representative and three Specialists. Logical identities, worker slots and model reservations are independent.

## Execution contract

A PostgreSQL-backed FastAPI control plane owns assignments, handoffs, deadlines, decisions and approvals. A separate worker performs typed, bounded actions against an isolated reference integration. SwiftUI provides the native Mac operator console and React provides the browser console. Task input and tool output are data. Only policy grants authority. Cross-department collaboration passes scoped summaries. An independent reviewer reproduces findings from primary evidence. The initiating operator accepts the result and exports its lineage.

## Reference operation

Compare a versioned API contract to a sandbox response. A premature-ticket instruction conflicts with a hold instruction. Hold the ticket branch, continue inspection, convene Representatives and a Director, collect dissent and a staffing commitment, and ask the operator for one decision. Require a separate exact-action approval for external dispatch. Seed a reporting defect, independently reject it, correct it and preserve both verdicts.

## Release gates

Release 0 requires the attended workflow, a configured model, restartable organization, lineage and portable evidence. Unattended deployment additionally requires measured contradiction isolation, delegation-loop termination, blocked approval bypass, crash reconciliation, independent QA, budget and access isolation, portable restore and bounded meetings. Use the same fixture, budgets and rubric for baseline comparisons. Use local adjudicated feedback by default. P1 follows these gates; see tasks/todo.md for implementation and outstanding evidence.

## Native operator experience

The macOS console uses SwiftUI and the same authenticated control API as the web console. Its primary navigation opens five operator-to-Representative conversations. Each message is durable, private to the signed-in operator and department thread, and processed by a bounded worker claim. On-device dictation produces an editable draft. Spoken replies are optional. Operational decisions use the existing policy-checked controls.
